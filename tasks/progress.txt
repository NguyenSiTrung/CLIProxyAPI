# Ralph Progress Log - Access Key Cost Limits

## Codebase Patterns
- Config structs in internal/config/config.go use yaml/json tags with kebab-case names
- Nested config structs are placed after the main Config struct definition
- Use `go build ./...` to verify backend compiles
- Cost module (internal/cost/) follows pattern: Calculator struct with sync.RWMutex for thread-safe access
- Accumulator uses JSON file format for persistence (map[string]float64)
- Manager uses coreusage.Detail from sdk/cliproxy/usage for token details
- Server integration: costManager field in Server struct, initialized in NewServer
- CostManager() getter method on Server provides access to middleware and handlers
- Data directory uses util.WritablePath() fallback pattern (same as logs)
- Middleware pattern: Create CostLimitMiddleware(manager) in internal/api/middleware/, register with v1.Use() after AuthMiddleware
- API key is stored in context as "apiKey" by AuthMiddleware - use c.Get("apiKey") to retrieve
- Usage plugin pattern: Create Plugin implementing coreusage.Plugin in internal/cost/plugin.go, register in init()
- CostLimitPlugin uses SetManager() pattern - set manager reference during server startup after cost.NewManager()
- Plugin only records cost for successful requests (check record.Failed == false)
- Management API handlers: Add methods to Handler struct in internal/api/handlers/management/, use SetXxx() to inject dependencies
- Management API routes: Register in registerManagementRoutes() in server.go with PUT and PATCH for update endpoints
